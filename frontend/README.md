# Timesheets Demo (frontend-only)

Vite React app with an in-process mock API. **No backend required.**

## Run

```bash
npm install
npm run dev
```

Open http://localhost:5173

## Demo logins

Click a role on the login page, or type credentials:

| Area | Username | Password |
|------|----------|----------|
| Admin (full access) | `admin` | `admin` |
| Internal user | `user` | `user` |
| Viewer (read-only) | `viewer` | `viewer` |
| Files & Vault only | `vault` | `vault` |
| Employee portal | `employee1` | `portal123` |

OTP / TOTP / captcha challenges (if you hit those flows) accept code **`123456`**.

## Deploy on Vercel (free Hobby)

1. Import repo; **Root Directory** = `frontend`
2. Framework **Vite**; Build `npm run build`; Output **`dist`**
3. Push — build runs `scripts/bundle-api.mjs` → single CJS `api/mock.js` + `api/health.js` (fixes ESM module-not-found on Vercel)

Demo data on Vercel is **in-memory** (resets on cold start; edits may not persist across instances). Local dev still uses `.demo-store.json`.

## Notes

- Mock lives under `mock/` and is wired via `mockApiPlugin()` in `vite.config.ts` (local) and `api/mock.ts` (Vercel).
- Serves `/health` and `/api/v1/*` in the Vite middleware (dev + preview).
- Mutations persist to `.demo-store.json` locally (survives browser refresh + Vite restart).
- **Reset** in the header restores **all** demo data (inbox, pipeline, employees, files, records, portal) and remounts every page. Viewer (read-only) cannot extract, archive, review, or edit.
- Or delete `.demo-store.json` and restart.
- Sample PDFs: generated by `mock/pdf.ts`, cached on the store, and also written to `public/demo/` on first load.
- Unknown `/api/v1/*` routes return `501` with `{ detail: "mock: not implemented …" }` so the UI does not hang.
